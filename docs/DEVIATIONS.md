# SENTINEL — Deviations from Frozen Architecture

This file records every intentional deviation from `docs/ARCHITECTURE.md`.

| # | Section | Deviation | Reason |
|---|---------|-----------|--------|
| 1 | Non-negotiable 16, §1 | Python **3.13.6** instead of 3.12. `requires-python = "==3.13.*"`. | The project venv (`backend/.venv`) was built with 3.13 and every pin was resolved against it. Python 3.12.2 *is* installed on the dev machine, so rebuilding the venv on 3.12 remains an option (open question). All stdlib APIs used (`tomllib`, `StrEnum`) exist in both. |
| 2 | Non-negotiable 16 | Dependency pins are the versions installed in the 3.13 venv (for example pandas 3.0.5, scikit-learn 1.9.1). | Pins follow the interpreter. `tests/unit/test_environment.py` asserts `sklearn.__version__` equals the pin so artifacts cannot be loaded under a different version silently. |
| 3 | §1 (`uv.lock`) | Lockfile is `backend/requirements.lock` from `pip freeze --exclude-editable`, not `uv.lock`. | `uv` is not installed on the dev machine. Install with `pip install -r requirements.lock` then `pip install --no-deps -e .`. |
| 4 | §1 | Money helpers live in `backend/sentinel/money.py` (`format_inr`, `make_money`). | Not in the §1 tree. Implements §4 "formatted once, server-side" and the §14.1 single `format_inr()` rounding rule in one place. |
| 5 | §3 | `decisions_core_immutable` protects every column except `current_action`, `status`, `latest_audit_event_id` (the contract lists 10 columns). Added CHECK constraints: `decisions.cost_optimal_action / recommended_action / current_action` and `audit_events.new_action` in the action set, `previous_action` NULL or in it, `selected_rule` in the three rules. | Strengthens the stated immutability and action vocabulary; no column, table or name changed. |
| 6 | §4 | `PolicyDecision` has a model validator: all four actions exactly once; PREPAID_ONLY and MANUAL_REVIEW feasible; outside `DEGRADED_MODE_FALLBACK`, selected is feasible and within ₹1 of the feasible minimum, `cost_optimal_action` within ₹1 of the overall minimum, and `selected == cost_optimal` iff `selected_rule == "MIN_EXPECTED_COST"`. `CheckoutRequest(ScoreOrderRequest)` added for the public route. `QueueItem.status/source` and `OrderSummary.delivery_speed` narrowed from `str` to the Literals used elsewhere in §4. | Enforces §9.1 invariants at the contract boundary. |
| 7 | §2 (`/health`) | `/health` (not in §4) returns `policy_version`, the first 8 chars of `policy_config_sha256`, and `demo_clock`; the sidebar renders the policy version from it. | Avoids a hard-coded "v1.0" in the UI. No money, scores or thresholds exposed. |
| 8 | §8.4 | Validator also rejects `floor > cap`, negative `*_inr`, `tie_tolerance_inr < 0`, `block_min_corroborating_signals < 2`, `high_exposure_min_p_abuse` outside `(0, block_min_p_abuse)`, and missing or unknown keys. The slope-order check returns the PREPAID/REVIEW swap region as **info**, not as an error. | Review items B13 and the Phase 1 brief. |
| 9 | §1 (frontend) | `vite.config.ts` declares `process` locally instead of adding `@types/node`. | Keeps the dependency list unchanged while injecting `X-Internal-Key` via the Vite proxy from `SENTINEL_INTERNAL_API_KEY`. |
| 10 | §9.1 | `argmin_with_tiebreak` takes the cent-rounded totals (`make_money(total).inr`) rather than raw `CostBreakdown.total`. | Rounding happens before the ₹1 tie comparison so the choice always agrees with the `Money` values stored in the decision and checked by the `PolicyDecision` validator. |
| 11 | §9.1, §9.3 | Policy inputs are a `DecisionContext` (p_abuse, p_return for the record only, V, CLV, the five `EvidenceSignal`s, `graph_state_as_of`, degraded flag). §9.2 signals are derived by `corroborating_signals(SignalInputs)`, where `SignalInputs` holds the §6.3 feature values plus a link weight per signal and the link kinds carrying any burst. | The contract names the inputs but not their container. Phase 3's FeatureBuilder will fill `SignalInputs`. |
| 12 | §9.2 | Interpretations: qualifiers in "Present when" decide `present` (burst reached only via address links, or confirmed abuse on a multi-tenant address, is not present); `counts_for_corroboration == present`; ACCOUNT_CLAIMS weight is 1.0 (account evidence, not a decayed link). | See open questions in the Phase 1 report. |
| 13 | §9.3 G4 | G4 fires on weakness only when at least one signal is present and all present signals weigh < 0.3; with zero signals G2 already removes BLOCK. Staleness compares `graph_state_as_of` with `DEMO_CLOCK − 24 h`. | Matches §11 Demo 3, where BLOCK is listed as removed by G2 and G3 only. |
| 14 | §9.1 G6 | Degraded decisions still compute and show all four costs at the supplied `p_abuse`; `cost_optimal_action` is the cost argmin; guardrails list is `[G1, G6]` with G6 removing BLOCK. | `PolicyDecision.costs` and `decisions.p_abuse` are required even in degraded mode. |
| 15 | §9.5 | `allow_all()` returns an `Action`, not a `BaselineOutcome` (§4 `BaselineOutcome.strategy` allows only FIXED_THRESHOLD and RULE_BASED). RULE_BASED thresholds are module constants, not config keys. FIXED_THRESHOLD takes τ as arguments; tuning on CALIBRATION is Phase 4. | Keeps §4 and the config key set unchanged. |
